# ROBIN Lab 디자인 고안서 — 레퍼런스별 강점만 정리

> 조사 기준일: 2026-07-24. 이 문서는 현재 공개된 레퍼런스 사이트에서 확인한 **잘 작동하는 원칙**만 기록한다. 특정 화면, 색상, 문구를 복제하기 위한 문서가 아니다.

## 한눈에 보는 결론

| 레퍼런스 | 가장 큰 강점 | ROBIN에 주는 교훈 |
| --- | --- | --- |
| RLLAB @ Yonsei | 신뢰를 만드는 절제와 최신성 | 적은 요소로도 연구실의 활동성을 증명할 수 있다. |
| Improbable AI | 연구 주제를 이해 가능한 연구 프로그램으로 번역 | 각 연구축은 제목·설명·핵심 항목·다음 행동을 가져야 한다. |
| Collaborative Robotics Lab | 협업·프로젝트 중심의 인간적인 서사 | 프로젝트는 논문 목록이 아니라 실제 문제와 사람을 보여주는 단위다. |
| Stanford ASL | 복잡한 연구를 계층화하는 정보 설계 | 큰 비전 아래 연구 스러스트, 시스템, 적용 분야를 순서대로 둔다. |
| UC Berkeley BAIR | 기관급 신뢰와 편집적 절제 | 브랜드보다 연구자·연구·성과가 먼저 읽히는 구조가 강하다. |

## 1. RLLAB @ Yonsei — 최소 구성으로 만드는 신뢰

URL: <https://youngwoon.github.io/>

### 잘한 점

- 내비게이션이 `Home / Group / Publications / Projects / Apply`로 매우 짧다. 방문자가 무엇을 찾는지 바로 알 수 있다.
- 첫 화면은 연구실 사진, 짧은 연구 소개, Apply 링크로 끝난다. 장식보다 실제 연구실의 존재를 먼저 보여준다.
- News가 시간 역순의 간결한 문장으로 축적된다. 논문 수락, 수상, 워크숍, 구성원의 진로, 공동연구를 빠르게 읽을 수 있어 연구실이 살아 있다는 인상을 준다.
- Publications의 `show all / show selected / show all by topic`은 많은 정보를 적은 조작으로 탐색하게 한다.

### ROBIN에 가져올 원칙

1. Home에는 가장 중요한 연구 선언 한 개와 최신 활동만 둔다.
2. News는 홍보 문구가 아니라 `날짜 + 사실 + 관련 링크`라는 연구 기록으로 쓴다.
3. Publications는 화려한 카드보다 최신순과 Topic 중심의 빠른 탐색을 우선한다.

근거: [RLLAB Home](https://youngwoon.github.io/), [RLLAB Publications](https://youngwoon.github.io/publications)

## 2. Improbable AI Research Lab — 연구축을 명확한 프로그램으로 표현

URL: <https://improbableai.com/index.html>

### 잘한 점

- MIT·EECS·CSAIL이라는 소속을 첫 화면 상단에 연결해 기관 신뢰를 즉시 만든다.
- 연구실 소개는 로보틱스와 AI의 범위를 한 문단으로 선명하게 규정한다.
- `Whole-Body Locomotion / Dexterous Manipulation / General Machine Learning`처럼 연구 주제를 서로 겹치지 않는 큰 프로그램으로 나눈다.
- 각 연구축은 설명문, 세부 역량 목록, `Explore Research` 행동으로 끝난다. 제목이 단순 라벨이 아니라 탐색의 출발점이다.
- Team, Papers, Blog를 바로 가는 경로로 제공해 연구 성과와 사람을 빠르게 확인할 수 있다.

### ROBIN에 가져올 원칙

1. `Robot Interface / Robot Interaction / Robot Intelligence`를 공식 ROBIN의 변하지 않는 연구축으로 둔다.
2. 각 축에 “무엇을 한다”뿐 아니라 “로봇이 무엇을 할 수 있게 되는가”를 적는다.
3. 축마다 대표 프로젝트·논문·영상으로 바로 가는 하나의 다음 행동을 제공한다.

근거: [Improbable AI Home](https://improbableai.com/index.html)

## 3. Collaborative Robotics Lab — 연구를 협업과 프로젝트의 언어로 바꾸기

URL: <https://collaborativeroboticslab.github.io/>

### 잘한 점

- 첫 소개에서 분야 목록보다 “서로 다른 전문성을 모아 복잡한 로봇 문제를 푼다”는 협업의 이유를 앞세운다.
- `Start a collaboration` CTA가 학생 모집과 별개로 존재한다. 산업·연구 파트너가 스스로를 위한 경로를 바로 찾을 수 있다.
- 프로젝트는 대표 이미지, 날짜, 책임자, 제목, 짧은 요약으로 반복된다. 이 형식은 연구가 누구의 어떤 문제 해결인지 빠르게 전달한다.
- Team과 Projects가 서로 이어져 구성원의 전문성과 연구 결과를 연결한다.

### ROBIN에 가져올 원칙

1. `Join ROBIN`과 `Collaborate with ROBIN`을 서로 다른 목표와 문구로 운영한다.
2. Projects는 과제명만 나열하지 말고, 문제·기간·지원기관·핵심 기여·관련 결과를 표준 필드로 둔다.
3. 실제 사진이나 연구 영상이 생기면 먼저 Project에 연결하고, 그 후 Home에서 대표 사례로 끌어온다.

근거: [Collaborative Robotics Lab Home](https://collaborativeroboticslab.github.io/), [Projects](https://collaborativeroboticslab.github.io/projects/)

## 4. Stanford Autonomous Systems Lab — 깊이를 가진 연구 체계

URL: <https://stanfordasl.github.io/>

### 잘한 점

- `Bringing world-scale intelligence to real-world machines.`처럼 넓지만 명확한 한 줄 비전으로 시작한다.
- Research, Hardware, Publications, Team, Join, Contact가 분리되어 연구·실험 장비·사람·지원 경로를 혼동하지 않는다.
- Research Thrusts는 Embodied AI, Physical AI Safety, Data Flywheels, Control, Applied Autonomy처럼 상위 질문을 먼저 제시하고, 그 아래의 시스템·방법·응용을 연결한다.
- 복잡한 내용을 단순 키워드 묶음이 아니라 `Perceive → Reason → Act` 같은 인과적 흐름으로 풀어낸다.
- Visual Highlights는 설명을 대체하지 않고, 연구 방향을 증명하는 보조 시각자료로 사용한다.

### ROBIN에 가져올 원칙

1. Home Hero는 ROBIN의 한 줄 비전만 말하고, Research 페이지에서 체계를 깊게 설명한다.
2. 3개 연구축은 따로 떨어진 카테고리가 아니라 `Interface → Interaction → Intelligence`라는 연결된 흐름으로 보여준다.
3. Hardware/Facilities 정보가 충분해지면 Research와 분리된 독립 페이지로 만든다.

근거: [Stanford ASL Home](https://stanfordasl.github.io/)

## 5. UC Berkeley BAIR — 편집적 절제와 기관급 정보 구조

URL: <https://bair.berkeley.edu/>

### 잘한 점

- BAIR는 방대한 분야와 구성원을 다루지만, 사이트의 목적은 연구 공동체를 명료하게 소개하고 발견하게 하는 데 있다.
- 연구 이니셔티브와 프로그램을 독립된 단위로 드러내며, 연구실 하나가 아니라 연결된 생태계라는 인상을 만든다.
- 과장된 제품식 인터랙션보다 텍스트, 사람, 연구 주제, 성과를 우선하는 편집적 밀도가 신뢰를 만든다.
- BAIR Blog는 전통적인 논문·학회 발표와 별개로 연구 결과를 이해하기 쉽게 전파하는 채널의 역할을 한다.

### ROBIN에 가져올 원칙

1. 첫 화면은 제품 랜딩페이지처럼 행동을 유도하기보다, 연구실의 정체성과 연구 방향을 강하게 선언한다.
2. 단색 기반, 넓은 여백, 큰 타이포그래피, 제한된 강조색으로 충분한 인상을 만든다.
3. 연구 성과의 깊이는 Publications, Projects, News에서 쌓고, Home은 그중 중요한 것만 편집해 보여준다.
4. 향후 콘텐츠가 쌓이면 논문 홍보와 별개로 짧은 연구 해설/랩 노트를 운영할 수 있다.

근거: [BAIR Home](https://bair.berkeley.edu/), [BAIR Blog overview](https://bair.berkeley.edu/blog/about/)

## ROBIN에 적용할 공통 원칙

1. **Hero는 하나의 선언이다.** 긴 기술 설명, 과도한 CTA, 장식적 인터랙션을 첫 화면에 몰아넣지 않는다.
2. **연구축은 연구실의 언어다.** 공식 원사이트의 `Robot Interface / Robot Interaction / Robot Intelligence`를 지속적으로 사용한다.
3. **성과는 실제 자료로 증명한다.** 영상, 논문, 프로젝트, 구성원, 뉴스는 각각 고유한 역할을 가진다.
4. **탐색은 단순해야 한다.** Home, Research, Projects, Publications, Team, Join, Contact라는 목적 기반 구조를 유지한다.
5. **시각 디자인은 연구를 보조한다.** 로고, 타이포그래피, 여백, 실제 연구 이미지는 강화하되 연구 내용을 대체하지 않는다.
